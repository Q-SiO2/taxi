## Recovery and stop rules

- No supply: use the visible retry/map-selection flow. Do not claim assignment
  until the native driver accepts and the server confirms it.
- Location unavailable/stale: stay offline and use the explicit fresh request.
  Do not weaken provenance, dispatch freshness or eligibility to continue.
- Network/unknown result: retain the visible pending/recovery state, reconnect
  and read the authoritative trip/payment before another consequential action.
- Expired MFA: cancel and sign in again through the normal flow. No security
  bypass, embedded credentials or unverified session restoration.
- If a beat fails, state the observed failure. A labelled capture from an older
  verified run can explain the expected result, but cannot count as a live pass.
