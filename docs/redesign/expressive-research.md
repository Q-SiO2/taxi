# Illustration, graphic decoration and motion research

**Research extension — 14 October 2026; proposed, not an adopted art direction.**
The owner found the earlier atlas too plain and asked for another deep internet
dive to conceptualize graphics and interesting animations. This investigation
looks beyond taxi layouts to product illustration systems, motion studios,
brand systems, native animation and accessibility. The result is an original
[visual atelier](expressive-board.html), [24 vector studies](expressive-assets.json),
[18 motion recipes](expressive-recipes.md) and [placements for every page](expressive-pages.md).

## What was inspected

The following 34 primary references were inspected through live source content
and search results. DoorDash and Rivian additionally received browser visual
walkthroughs. Not every portfolio film was watched; campaign case studies are
craft references, not evidence that the same animation belongs in a taxi UI.
Source owners' research/performance claims are not TaxiMobile results. The board
contains original vector studies, not downloaded artwork or recreated characters.

| [Compose animation introduction](https://developer.android.com/develop/ui/compose/animation/introduction) | Existing animation APIs cover visibility, values, transitions and timing. | Prefer cached drawing + Animatable / Transition / AnimatedContent. | [Compose graphics shapes](https://developer.android.com/develop/ui/compose/graphics/draw/shapes) | Polygon morphing uses a separate dependency and is not arbitrary path morphing. | Keep optional advanced morphing separate from the initial native implementation; do not pretend a simple API morphs any illustration. |

| [W3C pause/stop/hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html) | Moving content needs appropriate user control. | Play/Stop/Scrub in the board; finite decorative cycles, lifecycle cancellation and static fallbacks in the native plan. |

## Retrieval limits and rejected shortcuts

The old `airbnb.design/lottie/` page returned 404; the official GitHub source was
used instead. Older Carbon/IBM motion URLs failed, so current indexed/navigation
links were inspected. Apple's motion page required JavaScript and its markdown
link failed; it is not used here to support a detailed rule. Portfolio images
and films were not downloaded into runtime assets. These limitations are not
filled with invented observations or a claim that all reference animation was watched.

## Synthesis

1. Make a recognizable illustrated world: consistent taxi/object anatomy, layered
   architecture, cropped route rhythm and a small set of expressive poses.
2. Add visual texture through actual composition—ticket margins, interleaved
   bands, sparse dots, arches and object silhouettes—rather than making every
   surface another rounded rectangle.
3. Give each object a characteristic movement: taxi rolls, ticket opens,
   folio fans, notebook tilts, wave drifts and the Help object winks once.
4. Use motion as an authored sequence with a rest pose, trigger and cancellation
   rule. A decorative animation does not need to pretend it is a system result.
5. Compare Paper cut, Line chronicle and Print studio on actual page placements
   before choosing. The user's freedom to experiment remains intact; none is adopted.

The [native/art direction plan](expressive-motion.md) translates these findings
into concrete element sizes, timing, file boundaries, delivery order and acceptance.
