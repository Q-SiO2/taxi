## Proposed direction

Explore all five directions on equal terms. **Forest** is the initial design
recommendation: deep evergreen actions, pale mineral surfaces, mint selection
washes, charcoal text, and restrained apricot illustration accents. It offers a
clear departure from the rejected chrome without depending on decorative effects.
**Orchid**, **Electric**, **Terracotta** and **Graphite/Lime** are fully specified
alternatives, not token recolors to be automatically merged. Typography is an
independent choice: Inter/Noto Sans Arabic, Plus Jakarta Sans/Noto Sans Arabic,
or IBM Plex Sans/IBM Plex Sans Arabic. The board renders actual bundled fonts.

Passenger: Ride / Trips / Account as stable labelled destinations; Inbox and
Help remain accessible through Account, with Safety directly reachable on an
assigned ride. Driver: Work / Earnings / Account when idle; the current job owns
the active screen. The map carries locations and route information. Forms,
history, receipts and account work use dedicated pages, rather than competing
panels piled into a map sheet. Operations uses a coherent desktop workspace
with scope, queue, detail and reviewed action.

## Authority and boundaries

The existing [product](../product.md), [design](../design.md),
[API](../api.md), [auth](../auth.md), [rides](../rides.md),
[payments](../payments.md), [drivers](../drivers.md),
[operations](../operations.md) and [architecture](../architecture.md)
remain authoritative for behavior. This proposal deliberately challenges the
current visual prescriptions in [ui.md](../ui.md) and
[extended_ui.md](../extended_ui.md). Following approval, update those authorities
in one coherent change before feature implementation. Do not silently implement
a competing identity while the fixed old palette and font rules remain active.

Keep Kotlin Multiplatform/Compose, FastAPI/PostGIS, native maps and the existing
web module. Unlumen is interaction/finish inspiration; React, Tailwind and Motion
are not introduced into the application. Preserve session fencing, command gates,
privacy, server-owned pricing/payment/eligibility, optimistic versions and MFA.
Never add visible nearby taxis before assignment, imagined dispatch progress,
card entry, unsupported OTP, saved-place persistence or emergency integration.

The alpha keeps map selection, as already chosen by the owner. Provider-backed
place search gets its own later acceptance gate; no dead search field is used as
the alpha's primary action. A cached map cannot authorize a new booking offline.
